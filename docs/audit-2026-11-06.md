## 五、潜在问题与风险点

### 5.1 本轮新增的高优先级问题（重点发现）

**【高】`-Port` 参数与服务端实际端口脱节，非默认端口必然"启动失败"**

`start-app.ps1`（88–98 行）把 `$Port` 用于探活 URL 和浏览器地址，但 `Start-Process` 启动 Node 时未传递端口；服务端 `const PORT = Number(process.env.PORT) || 4399` 恒为 4399。执行 `-Port 5000` 时服务在 4399 启动、健康检查却轮询 5000，30 秒后报"启动失败"且**后台进程残留占用端口**；`stop-app.ps1 -Port 5000` 同样找不到目标。应删除 `-Port`，或在 `Start-Process` 前设 `$env:PORT = $Port` 由子进程继承。

**【高】强制杀进程绕过优雅退出，可能丢失最近写入**

`stop-app.ps1` 使用 `Stop-Process -Id $pidValue -Force`，而 `server/src/index.js` 的 `flushDb()` 仅在 `SIGINT` / `SIGTERM` 时执行；Windows 强制终止不投递信号，也不执行 Node 退出钩子。若恰在 `saveDbSoon()` 的 120ms 防抖窗口内，**最近一批增删改不会落盘**。此外脚本不校验进程名是否为 `node`，4399 被其他服务占用时会误杀无关进程。

**【中】`-AllowPublic` 是死参数，文案却引导用户使用**

`enable-lan.ps1` 的 `param` 仅声明 `Port`（已用 PowerShell 语法树只读解析确认），但第 61 行提示"也可以改用 `-AllowPublic` 参数"、第 65 行判断 `$PSBoundParameters.ContainsKey('AllowPublic')`。实际传该参数会被 PowerShell 直接拒绝（未声明），不传则该分支永不进入 → 公用网络放行功能完全不可用。需补 `[switch]$AllowPublic` 或删除该段文案与逻辑。

**【中】构建产物只在"不存在时"生成，代码更新可能看不到效果**

`start-app.ps1`（78–86 行）仅在 `web/dist/index.html` 不存在时执行 `npm run build`。而 `dist/` 被 gitignore、不随代码更新分发：只要本机留有一次旧构建，日后 `git pull` 拿到新的 `web/src` / `index.html` / `public` 都**不会触发重建**，用户会一直看到旧页面。当前 `dist` 恰好已在 10-31 重建（含新图标），属"隐患未发作"而非已修复。应比对源文件与 `dist/index.html` 时间戳自动重建，或提供 `-Rebuild` 开关并在 README 注明"更新代码后请重建"。

**【中】端口占用误判为"服务已运行"**

`Test-PortOpen` 仅做 TCP 连接探测，未校验 `/api/health` 返回体。4399 被其他程序占用时，脚本直接打开浏览器并跳过启动，用户看到的是别人的服务且无任何错误提示。

**【中】局域网暴露放大既有安全面**

服务端注释明确"不指定 host → 监听所有网卡"，配合 `cors({ origin: true })`（反射任意 Origin）、HTTP 明文、JWT 存 `localStorage` 且 12h 有效、登录页硬编码 `admin/admin123` 一键填充 —— 一键脚本把系统推向"同一 WiFi 多人访问"后，上轮的"演示账号"从中风险升级为**首要风险**。另 `requireAuth` 仍兼容 `?token=` 查询串鉴权，Token 可能进入日志 / Referer。

**【低】其他**

- `enable-lan.ps1` 的 `Set-NetConnectionProfile -NetworkCategory Private` 修改的是**全局网卡网络类别**（影响该网卡上所有应用的防火墙宽松度），脚本只打印一行还原命令，不记录原值、不提供还原脚本。
- `启用局域网访问.cmd` 提权用 `Start-Process -FilePath '%~f0' -Verb RunAs`，**未透传 `%*`**，提权后自定义参数丢失；`net session` 判管理员在部分 Windows 版本不可靠。
- SPA 兜底 `app.get('*')` 会把任何非 `/api` 的 GET（含缺失的 `/favicon.ico`）返回 `index.html`，资源缺失时浏览器拿到 HTML 当图标，**静默失败不报 404**，不利于排查构建产物不一致。
- 启动日志重定向为**覆盖**而非追加，每次启动丢失上次排障线索；Node 版本提示写"18 或更高"，与根 `package.json` 的 `engines: node >=20` 及 README 不一致。
- `favicon.ico` 28KB 偏大（多尺寸 ICO），对首屏影响极小。

## 六、可落地的改进建议

### P0（交付前必修，约 0.5–1 人日）

1. **修脚本端口一致性**：`start-app.ps1` 启动前 `$env:PORT = $Port`（子进程继承），或删除 `-Port`；`stop-app.ps1` 同口径。Node 版本提示改为 `>=20`。
2. **安全停止服务**：先按 `OwningProcess` 校验进程名为 `node` 且命令行含 `src/index.js`；去掉 `-Force`，改用能触发 `SIGTERM` 的方式以执行 `flushDb()`；启动脚本用 `-PassThru` 把 PID 写入 `logs/server.pid` 供精确停止。
3. **修复 `-AllowPublic`**：在 `param` 补 `[switch]$AllowPublic`，否则删除第 61 行文案与 65–73 行死分支；提权命令补 `-ArgumentList` 透传 `%*`。
4. **构建产物一致性**：比对 `web/index.html`、`web/src/**` 最新 mtime 与 `dist/index.html`，过期自动 `npm run build`；SPA 兜底改为静态资源找不到时返回 404 而非 `index.html`。
5. **局域网暴露前置门禁**：演示账号块改由 `import.meta.env.DEV` 控制（或首次启动强制改密）；收敛 `cors` 白名单、移除 `?token=` 鉴权分支、补 `helmet` / CSP。

## 七、结论

本轮更新把项目从"需要命令行启动的开发者项目"推进到**可双击交付的内网应用**：图标资源补全、README 部署说明详尽、防火墙策略保守，产品化方向正确；`tsc` 严格检查通过，前端源码本身稳定、未引入回归。

但需明确两点：

1. **上轮指出的前端 P0 缺陷一项未修**（`web/src` 零改动），且"演示账号 + 一键局域网共享"叠加后风险反而放大；
2. **新增运维脚本存在 3 个确凿逻辑错误**（`-Port` 与服务端口脱节、`-AllowPublic` 未声明、构建产物不自动刷新）和 **1 个数据安全风险**（`Stop-Process -Force` 绕过 `flushDb`）。

建议按 P0 的 1–6 项在交付前处理：改动量小，却直接决定"更新代码后能不能看到变化"与"多人共用会不会丢数据"。
