## 三、问题清单

### P0-1 停止脚本会停错服务（已实测复现）

`scripts/stop-app.ps1:26-36`：只要 `logs/server.pid` 存在且进程像本项目服务，就直接加入目标，**完全不看 `-Port`**。

实测：请求停止 4406（该端口上是另一个程序），脚本杀掉的是 **4399 上的生产服务（PID 8516）**，随后还因为 4406 未监听而打印「服务已停止」。更糟的是 `:69` 会删掉 PID 文件，掩盖了真实发生的事。

修复建议（PID 必须与端口互相印证）：

```powershell
if ($savedPid -gt 0 -and (Get-Process -Id $savedPid -ErrorAction SilentlyContinue) -and (Test-OurServer $savedPid)) {
  $onPort = Get-NetTCPConnection -LocalPort $Port -State Listen -ErrorAction SilentlyContinue |
    Where-Object { $_.OwningProcess -eq $savedPid }
  if ($onPort) {
    $targets += $savedPid
  } else {
    Write-Host "PID 文件记录的服务（$savedPid）不在端口 $Port 上监听，改按端口查找。" -ForegroundColor Yellow
  }
}
```

### P0-2 导入 upsert 可绕过行级权限（已实测复现）

`server/src/routes/tables.js:360-369`：命中已有行时直接 `target.data = {...}`，**没有 `canEditRow(user, table, target)` 校验**；而 `PATCH /:id/rows/:rowId` 是有校验的（成员改他人行返回 403）。

实测：管理员建行 `X-1`，成员张三用 Excel 导入（`mode=upsert, dedupeKey=code`）→ `200 updated=1`，管理员那行被改名成「成员导入覆盖的名称」，`createdBy` 仍是管理员。

同类路径：`ledger.js` 的导入 upsert、`tables.js` 的 `sync-ledger` 覆盖台账行。

修复建议：命中目标行时先判权，无权限则计入 `skipped` 并回报，而不是静默覆盖。

### P0-3 `mode=upsert` 缺 `dedupeKey` 时静默退化为「全部新增」（探针唯一失败项）

`server/src/routes/tables.js:321`：校验写成 `if (mode === 'upsert' && dedupeKey && ...)` —— `dedupeKey` 为空时整段校验被跳过，`360` 的 upsert 分支同样不成立，于是逐行 push。

实测：`{mode:'upsert', mapping:{...}}`（不传 dedupeKey）→ `200 inserted=2`，与「更新」预期完全相反。前端有拦截，但接口层是敞开的；`mode` 也没有白名单（`mode:'UPSERT'` 同样退化成新增）。

修复建议：

```js
if (!['append', 'upsert'].includes(mode)) throw new HttpError(400, '导入方式不合法');
if (mode === 'upsert') {
  if (!dedupeKey) throw new HttpError(400, '请选择用于判断重复的字段');
  if (!pairs.some(([k]) => k === dedupeKey)) throw new HttpError(400, '用于判断重复的字段必须参与列映射');
}
```

### P1-4 台账编辑没有归属校验，与表格行规则自相矛盾

`server/src/routes/ledger.js:135` 的 `PATCH /:id` 无任何权限判断（`DELETE` 有）。实测成员改管理员的台账 → `200`，备注被改。

表格行已经按「创建者/表格创建者/管理员」收紧，台账却「登录即可改」，两套口径。FIX_REPORT 把这条列为「文档澄清」，但文档化不等于合理：同一个系统里两条数据规则不一致，用户和前端都难以预期。

建议二选一并写进 README 与测试：
- 严格：`req.user.role !== 'admin' && entry.createdBy !== req.user.id` → 403（与删除一致）；
- 宽松：表格行也放开（不推荐，现有 UI 已经有 `canEdit` 语义）。

### P1-5 非法数字被静默写成 0

`server/src/routes/ledger.js:94`：

```js
payload[f.key] = raw === '' || raw === null ? 0 : Number.isFinite(n) ? n : 0;
```

实测 `POST /api/ledger {price:'abc', quantity:'x'}` → `201`，落库 `price=0 quantity=0`。导入路径已经做了严格校验（返回「不是有效数字」），单条接口反而更宽松，属于漏改。表格行的 `normalizeRowData` 对数字列也有类似「转 null」的静默行为。

建议返回 400 并指出字段名，与导入路径保持同一套校验。

### P1-6 落盘策略：从「丢 120ms」换成「写放大」

`server/src/db.js:56-67` 把防抖从 120ms 改成 `setTimeout(0)`。好处是不会再因为强杀丢 120ms 数据（实测强杀后数据完整）；代价是**每个写请求都整份重写 JSON**。

实测：顺序 20 次 PATCH → 20 次落盘；并行 20 次 → 4 次。当前库 46KB 无所谓；5,000 行约 1–2MB 时，每次编辑都是同步全量写盘并阻塞事件循环。

建议折中：`setTimeout(..., 30~50)` + 退出时 `flushDb()` + 每 5s 兜底 flush；或直接把存储换成 SQLite（`node:sqlite` 已内置于 Node 22+，可零依赖）。

### P1-7 脚本无法无人值守运行

- `stop-app.ps1:52`：没有可停服务时 `Read-Host` 会永久阻塞自动化调用。
- `start-app.ps1`：经管道调用时（`powershell -File ... | Select-Object`）服务已起、脚本已退出，但调用方 180s 仍收不到 EOF，后台 job 一直挂着；本次实测留下孤儿 node 进程（PID 6192）。双击 `.cmd` 路径不受影响。
- 建议：加 `-NonInteractive` 开关统一控制暂停与提示；`Start-Process` 增加 `-RedirectStandardInput` 或改用 `cmd /c start /b` 以避免句柄继承。

### P2-8 死接口与无上限查询仍在

`server/src/routes/tables.js:184` 的 `GET /:id/rows/all` 与 `ledger.js` 的 `GET /all`：前端已不再调用，服务端仍暴露且无分页上限。建议删除，或加 `limit` 与「仅管理员可全量导出」的限制。

### P2-9 台账分页不做 URL 回写

`web/src/pages/TableDetail.tsx:198` 会在服务端夹取页码后回写 URL；`web/src/pages/Ledger.tsx:461` 只写 `page/pageSize`，没有夹取回写。手动访问 `/ledger?page=99` 会显示第 2 页数据，但分页器没有高亮页。照抄 TableDetail 的两行即可。

### P2-10 保存态判断仍晚于异步校验

`web/src/components/RowFormModal.tsx:38/46`：先 `await form.validateFields()` 再 `setSaving(true)`，快速双击仍有极小窗口提交两次。把 `setSaving(true)` 放到校验之前、失败时回滚即可。

### P2-11 网络异常时仍会退回登录页

`web/src/auth.tsx:29-34`：网络错误保留 token（好），但 `setUser(null)` 会让路由守卫跳登录页，注释里说的「不踢下线」只在 token 层成立。若想真正做到，需要在本地缓存一份用户信息，或在 `/auth/me` 失败时保留旧 user 并提示「连接中断」。
